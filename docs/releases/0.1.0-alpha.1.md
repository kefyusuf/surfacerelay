# SurfaceRelay 0.1.0-alpha.1 preparation plan

The owner selected `0.1.0-alpha.1` as the first experimental public-version target.
This authorizes preparation and local candidate verification. It does not
authorize registry publication, tags, GitHub Releases, repository settings changes
or formal decision promotion. Publication remains NO-GO until the gates below close.

## T-902 application acceptance matrix

The application must install the candidate, rather than load repository source
or a path package. Fixture-only pass-through policy stages do not qualify.

- A permitted actor succeeds only within its trusted tenant and resources.
- Unauthenticated/unauthorized actors and forged tenant/resource fields cannot execute.
- Switching authenticated actor or tenant after approval cannot reuse that approval.
- Changed input/record/selection, expired receipt and replayed receipt cannot execute.
- Concurrent attempts against one receipt and required idempotency key cannot
  duplicate the effect; shared-store evidence is required.
- Successful and rejected operations preserve output policy and safe audit evidence.
- Missing/stale bindings and unsupported drivers fail closed.

Use controlled application effects and fake external services; real purchases
or irreversible external operations are outside this acceptance test. Record the
actual installed versions, policy wiring and bounded results. Native agent and
all-platform qualification remain outside the alpha claim.

## Current candidate and publication-tooling limits

T-901 uses existing M8 local builders. The browser candidate deliberately retains
`private: true`; its README says it is not a public release. It cannot serve as
the final npm publication artifact unchanged. Source package version remains
`0.0.0-dev`; Laravel source metadata has no version field.

The current readiness function always returns NO-GO and a fixed conservative
blocker list. Its `public-version-not-approved` string is an M8 default, not a
live determination of the owner's target selection recorded here. No guardrail
or blocker is removed merely because a version was selected. T-903 must prepare
the publication path through reviewed changes, including appropriate staged
metadata and distribution-channel behavior. Do not bypass existing guards or
relax the private local-candidate contract to create publication permission.

Private GitHub vulnerability reporting was enabled with owner authorization on
2026-10-06 and rechecked. SECURITY.md assigns owner triage. D-069–D-074 and
D-076–D-078 are Accepted; D-026/D-075 stay Proposed. Registry ownership and
credentials remain unverified; no registry publication or remote mirror exists.

## Final go/no-go criteria

All T-901–T-903 gates must pass, with no open blocking correctness/security
finding. The final revision/version, exact publication artifact identities/hashes,
required decision dispositions, changelog/migration notes, security channel and
registry authority must be recorded and reviewed. The owner then explicitly
authorizes the T-904 publication action and intended prerelease distribution.

Local candidate success is preparation evidence. It does not imply publication
eligibility, permanent support, or a guarantee that later source revisions pass.

[compatibility](../VERSIONING-COMPATIBILITY.md) and
