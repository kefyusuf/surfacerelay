# SurfaceRelay 0.1.0-alpha.3 release plan

Status: Published on npm/Packagist; actual registry acceptance passed.
See the [publication record](0.1.0-alpha.3-publication.md).
T-911 uses the established
coordinated Laravel/browser release policy. Both artifacts must use one reviewed
source revision and version, even though Laravel runtime bytes are unchanged.

## Frozen scope

Only `surfacerelay/laravel` and `@surfacerelay/browser-runtime`. The browser adds
T-910/D-075's opt-in `FilamentBrowserDriver`, `FilamentSelectionCoordinator`,
`GlobalFilamentSelectionRuntime` and their types. Default Livewire and alpha.2
execution-envelope behavior remain compatible. No core contract change, new
dependency, MCP/OpenAPI publication, production or performance claim is included.

All helpers for a component must share a coordinator. Exposed tools determine
selection requirements; preserve exact binding objects. Framework preflight and
owned descriptor validation precede deferred selection writes. Ordinary UI calls
are outside helper exclusion and partial selection writes are not transactional.
Server authorization, selection, confirmation and idempotency remain authoritative.
Native Completed is not business success; inspect state before explicitly retrying
an unknown outcome. See [migration guidance](../consumers/browser-runtime.md).

## Gates and sequence

1. Update release-facing documentation and existing CI to alpha.3. Exercise the
   new exports/types, ordinary registry/envelope behavior and rejection before
   side effects through the installed package root; retain blocked deep imports.
2. Build from a clean exact Git archive in owned Docker isolation. Produce
   private candidates, then separate public artifacts with the existing builders.
   Verify package identity, every manifest byte and archive hash. Development
   metadata and private NO-GO guards remain unchanged.
3. Run clean npm import/typecheck/bundle/smoke, installed Laravel HTTP/shared-store
   controls, and the modern Filament consumer using the final public tarball.
   Exercise native Chrome selection drift, human approval, response loss and
   explicit replay with SQL effect evidence. Keep local and registry proof separate.
4. Run canonical validation, relevant regressions and independent review. Open
   a dedicated PR; require green exact-head checks before merge. Rebuild and verify
   final artifacts from the exact merged release revision before registry writes.
5. Verify existing owner authority and immutable source/mirror mappings. Publish
   only reviewed bytes under alpha.3; never move existing tags or promote latest.
   Use owner-interactive authentication if required; authentication is not proof
   of publication. Record partial publication accurately if only one step succeeds.
6. Download actual registry artifacts, compare every file and run fresh consumers
   plus native/SQL controls. Record hashes and source mapping in durable receipts.
7. Remove only task-owned Docker/demo/staging/browser resources; preserve existing
   images, user locks and personal tabs. Select no next task automatically.
