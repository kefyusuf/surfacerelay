# SurfaceRelay 0.1.0-alpha.2 release plan

Status: Published and registry-verified; see the [publication record](0.1.0-alpha.2-publication.md).
The completed plan below retains its gate order. The owner approved continuing the proposed sequence of
tracking cleanup, coordinated alpha.2 preparation, publication and fresh registry
consumer verification. Actual registry writes and evidence are recorded separately.

## Frozen scope

Only `surfacerelay/laravel` and `@surfacerelay/browser-runtime`, with coordinated
`0.1.0-alpha.2` identity from one exact reviewed source revision. The Laravel
runtime behavior is unchanged from alpha.1; its coordinated release retains the
existing package policy. The browser adds the explicit opt-in WebMCP execution
envelope implemented under D-079/T-908. Default behavior remains compatible.
Consumers opting in must inspect the envelope and nested application status;
native Completed alone is not business success. Unknown outcomes never permit
automatic retry. See [migration guide](../consumers/browser-runtime.md).

Source package metadata remains development-only. Public metadata exists only
in separately generated final artifacts. Existing private builders/readiness
and preview guardrails retain NO-GO and grant no publication authority.
MCP/OpenAPI publication, D-075 productization, new drivers, API redesign,
dependency upgrades, unattended credential provisioning and production claims
are outside T-909.

## Gates and sequence

1. Correct current tracking and second-alpha package documentation; make existing
   CI publication/installed-application jobs explicitly exercise alpha.2. Use
   public artifact-builder RED/GREEN for any demonstrated behavior defect.
2. Build private candidates from a clean exact Git archive, then separate final
   public artifacts. Verify archive hashes, every manifest byte, package identity,
   public npm root-only exports and alpha publishConfig. Keep both packages tied
   to the same source revision/version; no monorepo/path/dev-main shortcuts.
3. In task-owned Docker consumers run public npm import/typecheck/bundle/smoke
   and blocked deep import, Laravel installed HTTP authorization/mutation and
   two-process confirmation/idempotency races, and Filament native/SQL envelope
   acceptance. Clearly separate private candidate, final public and registry proof.
4. Complete canonical validation, relevant regressions and independent review;
   use a dedicated branch/PR and green exact-head CI before integration. Freeze
   merged release source and rebuild/reverify final artifacts at that revision.
5. Recheck namespace/owner authority without reading or sharing credentials.
   Use the existing `kefyusuf` identity and owner-interactive device/passkey route
   where required. Missing authentication cannot be treated as publication proof.
6. Prepare the existing Laravel distribution mirror from the final public tree,
   verify every file and source mapping, then tag source/mirror consistently.
   Publish the exact npm tarball with the alpha tag. Never move existing tags or
   overwrite alpha.1 artifacts. Inspect actual dist-tags; do not silently promote
   a stable/latest version.
7. Download the actual registry tarball/Composer distribution, compare reviewed
   bytes/source mapping, and run fresh consumers plus Chrome/SQL controls. Record
   partial publication as partial if only one registry step succeeds; no fabricated
   success, automatic retry of publication, or rollback claim.
8. Retain a durable receipt/release record; update current tracking. Remove only
   owned Docker/demo/browser/helper resources and preserve existing resources,
   source locks and personal browser state. Do not start another development task.

## Proof limits

Experimental prerelease: no stable API, production-security guarantee, support
SLA, general native interoperability or performance promise. Simulated checkout
is not real payment/bank 3DS. Receipt/idempotency races use the actual shared
fixture stores; native serial Filament tests do not qualify broad concurrency.
Codex in-app loopback failure remains outside accepted Chrome qualification.
